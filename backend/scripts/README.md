# backend/scripts — разовое и служебное

Здесь лежит то, что **не работает в проде постоянно**: бэкфиллы, сидеры, разовые миграции
данных, генераторы шаблонов. В `app/` остаётся только код, который обслуживает запросы.

Раньше всё это лежало вперемешку с `main.py` и `models.py` — одиннадцать отработавших
скриптов на десять живых модулей. По имени файла отличить «это крутится в проде» от «это
запускали один раз в марте» было нельзя.

## Как запускать

```
docker exec finance_backend python -m scripts.<имя> [аргументы]
```

Именно `-m`, а не `python scripts/<имя>.py`. Второй способ падает на
`ModuleNotFoundError: No module named 'app'`: при запуске файлом `sys.path[0]` становится
`/app/scripts`, а `/app` в путях не оказывается. При запуске модулем в путях — текущий
каталог, то есть `/app`. Ради этого рядом лежит `__init__.py`.

Почти у каждого скрипта есть сухой прогон, и по умолчанию он именно сухой — запись
включается флагом `--apply` или `--commit`. Точная форма написана в docstring самого
скрипта; сначала читаем его, потом запускаем.

## Что здесь

| Скрипт | Что делал |
|---|---|
| `import_new_deals.py` | обёртка над `app.sales.bitrix.deal_import` — довоз новых сделок из Битрикса |
| `import_publishers.py` | первичный ввод площадок из «Аптеки — Рабочая.xlsx» |
| `backfill_publishers_v3.py` | добор полей площадок под схему v3 |
| `backfill_counterparty_requisites.py` | реквизиты и счета контрагентов из выгрузки |
| `backfill_vat_articles.py` | ставки НДС и статьи по умолчанию из свежих операций |
| `backfill_deal_codes.py` | проставление шестизначных меток сделкам |
| `migrate_media_kit_to_documents.py` | медиакиты площадок в общий реестр документов |
| `apply_stage_bindings.py` | привязки стадий Битрикса к нашему каталогу |
| `seed_our_stage.py` | заполнение `our_stage_id` у сделок |
| `fix_deal_gross_2026_08_13.py` | разовая правка сумм с НДС |
| `mp_build_template.py` | генератор стартового Excel-шаблона медиаплана |
| `mp_tokenize_template.py` | обратная сборка: выгрузка МП → шаблон с токенами |
| `load_pipeline_stages.py` | первичная загрузка воронок и стадий из Битрикса |
| `load_sales_from_xlsm.py` | шаг 2 импорта продаж из «Дашборд по продажам.xlsm» |

Отработавшие скрипты **не удаляются**. Они объясняют, как данные пришли в нынешнее
состояние, — а на этот вопрос ни код, ни схема не отвечают.

## Чего здесь нет и почему

Репозиторий на GitHub публичный, поэтому сюда идут только скрипты **без опознавательных
данных**. Всё, что несёт реальные реквизиты, названия контрагентов или доступы, живёт в
корневой папке `scripts/` — она в `.gitignore` целиком: `change_admin.py`,
`fill_pm_requisites.py` (расчётный счёт), пентест-набор, `.bat`-помощники и часть разовых
правок данных. Правило выбора папки — в `backend/migrations/README.md`.

Два перенесённых загрузчика (`load_*.py`) раньше лежали в корневом `scripts/`, но при этом
уже отслеживались гитом, а их docstring ссылался на путь `/app/scripts/`, которого в образе
не было: контекст сборки бэкенда — папка `backend/`. Теперь путь настоящий.
