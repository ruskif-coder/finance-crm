# Эксплуатация

Что такое прод, как туда попадает код, и куда идти, когда что-то случилось.

> Прежняя редакция этого файла описывала домашний Windows-сервер с Docker Desktop,
> `backup_finance.bat` и Task Scheduler. **Той машины больше нет.** Документ, описывающий
> несуществующий контур, хуже отсутствующего: по нему ищут файлы, которых нет, и делают
> шаги, которые ничего не делают. Переписано 11.09.2026.

## Что такое прод

| | |
|---|---|
| машина | Ubuntu VPS, `timon.simbad.pro` |
| проект | `/root/finance` |
| сервисы | восемь контейнеров: две базы, бэкенд и фронт ядра, бэкенд и фронт кабинета, сайдкар печати, Caddy |
| наружу | только Caddy, порты 80/443. Всё остальное — на `127.0.0.1` |
| HTTPS | Let's Encrypt через Caddy, автоматом |
| доступ | собственный логин системы (JWT + RBAC). Не VPN и не список адресов |
| сосед | на том же хосте живёт другой продукт; Caddy делит их по доменам |

Кабинет паблишера и песочница креативов — отдельные домены в том же `Caddyfile`.

## Выкладка

Разработка на Windows → `git push` → на сервере `deploy.sh`.

```bash
ssh root@<сервер>
cd /root/finance
bash deploy.sh backend      # git pull + docker cp + restart
bash deploy.sh frontend     # git pull + docker cp + пересборка Next
bash deploy.sh full         # docker compose up -d --build
```

### Три вещи, о которых скрипт не знает

1. **`git pull` может не пройти.** На проде `docker-compose.yml` и `Caddyfile` **постоянно
   локально изменены** — там сервис бэкапов, общая сеть с соседом, домен соседа. Как
   только входящий коммит их касается, pull обрывается, и `set -e` кладёт всё действие
   **до** копирования файлов. Порядок сохранения — ниже, в runbook по выкладке.
2. **`docker cp` доносит не всё.** Действие `backend` копирует только `backend/app`.
   Смена `requirements.txt`, `backend/scripts/`, сайдкара печати — **требует `full`**.
3. **`Caddyfile` не применяется даже при `full`.** У сервиса `caddy` нет `build:`, и
   compose его не пересоздаёт. Правка маршрутов требует явного
   `docker compose up -d --force-recreate caddy`.

## Принятые риски

Это **не** список задач. Это то, про что уже решено «терпим», с условием пересмотра.
Оператор должен знать о них заранее, а не открывать заново.

| риск | почему терпим | когда пересмотреть |
|---|---|---|
| Публичный адрес, только логин и пароль. Ни 2FA, ни списка адресов | осознанная модель доступа; вход защищён блокировкой по учётке и по адресу | требование со стороны клиента или первый разбор перебора |
| Дампы лежат открытым текстом рядом с продом | шифрование не заведено | появление второго носителя / выноса копий наружу |
| Копии только на той же машине | отказ диска уносит и базу, и копии | как только появится куда возить |
| `uploads` (договоры, креативы, письма о правах) в дамп БД не входят | их бэкапит отдельный сервис, но он не на всех контурах | потеря диска |
| Боевая запись в ОРД закрыта третьим замком — переменной, которой нет в compose | необратимая запись в госреестр; включение должно требовать осознанного действия | первая настоящая отправка, по runbook |
| Деньги хранятся как `float` | одна валюта, расхождений в отчётах нет | вторая валюта или требование отчётности |
| Очередь трафика общая: вердикт может поставить любой с правом | решение владельца 03.09.2026 | ошибочные вердикты по чужим кампаниям |
| Тяжёлые отчёты грузят всё и режут период в Python | замер 11.09.2026: 6–31 мс на боевых объёмах, запас на десятилетия | `p95 > 2 с` или рост журнала операций на порядок |
| Ручные SQL-миграции вместо Alembic | осознанный отказ | рост команды или частые релизы схемы |
| Ядро ходит в базу суперпользователем | порт только на `127.0.0.1`, SQL нигде не склеивается строками | **в работе** — отдельная роль планируется |
| Сайдкар печати без аутентификации | наружу не опубликован | **отложено** до появления общего секрета |

## Секреты

`.env` в гит не попадает и не должен. Если он где-то засветился — менять значения сразу:
смена ключа подписи разлогинит всех, смена пароля базы требует `ALTER USER` внутри
контейнера (правки `.env` для уже существующей базы недостаточно).

Токены внешних систем кладёт владелец. Из переписки они не переносятся.
