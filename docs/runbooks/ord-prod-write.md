# Боевая запись в ОРД

> **Запись в ЕРИР необратима.** Её нельзя отозвать, переименовать или удалить. Дубль в
> реестре остаётся дублем навсегда. Всё, что написано ниже, существует только поэтому.

## Три замка

Чтобы отправка ушла в боевой контур, должны совпасть **три** условия:

| замок | где | по умолчанию |
|---|---|---|
| контур | `ORD_ENV` в `.env` | `demo` |
| разрешение | `ORD_ALLOW_PROD_WRITE` | **переменной нет в `docker-compose.yml` вовсе** |
| право | `ord_submit:create` у роли | только у двух ролей |

Третий замок — отсутствие переменной в compose — заведён намеренно и закреплён тестом
`test_env_passthrough`. Двух замков сочли мало: включение боевой записи должно требовать
правки конфигурации, то есть отдельного осознанного действия, а не строчки в `.env`.

**Снимать этот замок можно только решением владельца.**

## Перед первым включением

- [ ] в кабинете ОРД заведены и подтверждены наши юрлица;
- [ ] договорная цепочка собрана: изначальный договор → доходный → расходный;
- [ ] у бренда проставлен код ККТУ — без него реестр креатив не примет;
- [ ] свежий бэкап основной базы;
- [ ] понятно, на каком объекте делается первая отправка, и он один.

## Порядок

```bash
ssh root@<сервер>
cd /root/finance
cp docker-compose.yml /root/compose.prod.$(date +%F).bak

# 1. контур
#    в .env:  ORD_ENV=prod

# 2. снять третий замок — добавить в environment сервиса backend:
#       ORD_ALLOW_PROD_WRITE: ${ORD_ALLOW_PROD_WRITE:-}
#    и в .env:  ORD_ALLOW_PROD_WRITE=1

docker compose up -d backend

# 3. убедиться, что контур именно тот
docker exec finance_backend python -c "from app.ord import client; print(client.env())"
```

## Отправка

Через интерфейс, **не через curl**. Кнопка «Выпустить ЕРИД» спрашивает подтверждение и
показывает контур: при `prod` блок красный и подписан «запись уходит в реестр навсегда».

Сразу после первой отправки:

- [ ] маркер появился у комплекта;
- [ ] в кабинете ОРД видна ровно **одна** новая запись, не две;
- [ ] на вкладке **Аккаунты → ОРД → Зависшие отправки** пусто.

## Если отправка зависла

Строка попадает в «Зависшие отправки», когда запрос ушёл, а ответ не вернулся: создалась
запись у оператора или нет — **неизвестно**. Повтор по этой сущности закрыт, и это защита.

Снять блокировку можно **только сходив в кабинет ОРД и посмотрев глазами**:

| что в кабинете | что нажать | что будет |
|---|---|---|
| записи нет | «записи нет» | попытка закрыта, повтор разрешён |
| запись есть | «запись нашлась» + её идентификатор | попытка закрыта, **повтор остаётся запрещённым** |

Отвечать наугад нельзя: «записи нет» открывает повтор, и при неверном ответе в реестре
появится второй объект.

## Вернуть замки на место

После первой отправки, если боевой режим не нужен постоянно:

```bash
# убрать ORD_ALLOW_PROD_WRITE из docker-compose.yml
docker compose up -d backend
docker exec finance_backend python -c "import os; print(os.getenv('ORD_ALLOW_PROD_WRITE'))"   # None
```

Оставлять снятым «чтобы не возиться» — значит убрать предохранитель с необратимого
действия ради удобства одного дня.

## Что осталось несделанным

Экрана регистрации договоров в интерфейсе нет — боевой путь идёт через импорт выгрузки и
сверку. Обязательные поля (адрес, срок оплаты) подсказываются, но отправку не блокируют.
Оба пункта в работе; пока их нет, проверять руками по чеклисту выше.
