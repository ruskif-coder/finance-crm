# Справка для Claude Design: техническая база проекта Finance SIMB-AD

Цель — чтобы концепт интерфейса можно было завести в проект без переписывания с нуля. Ниже — реальные ограничения и конвенции текущего кода.

## Стек и ограничения сборки

- Next.js 14.2.3 (Pages Router, **не** App Router), React 18.3.1, Recharts для графиков.
- Backend на FastAPI/PostgreSQL — для UI-дизайна не важен, эндпоинты `/api/*` уже существуют.
- Контейнер фронтенда собирается `next build` и запускается `next start` (production-режим, не dev). Любой код должен быть валиден для продакшен-сборки.
- Никаких новых npm-зависимостей: в проекте нет Tailwind, CSS-модулей, styled-components, UI-кит библиотек (MUI/Ant/Chakra и т.п.). Если Claude Design выдаст компоненты на их основе, их придётся переписывать на чистый inline-style — лучше сразу попросить вывод без них.

## Стилизация

- 100% инлайн `style={{...}}` на уровне JSX-элементов. Общих style-файлов под компоненты нет.
- Единственная общая поверхность стилей — CSS custom properties в `frontend/styles/globals.css`:
  `--primary` (#2563eb), `--success` (#16a34a), `--danger` (#dc2626), `--warning` (#d97706), `--bg` (#f5f6fa), `--card` (#ffffff), `--border` (#e5e7eb), `--text` (#1a1a2e), `--muted` (#6b7280).
  Новый дизайн должен использовать эту палитру, а не вводить свою.
- Шрифт — системный стек `-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`. Кастомные веб-шрифты не используются.
- Цвета банков (АльфаБанк/ОПТ Банк/Совкомбанк/Наличные) — локальные константы (`BANK_STYLES`/`BANK_COLORS`) в каждом файле, где нужны. Если дизайн трогает таблицы операций/баланс по банкам — важно сохранить узнаваемость этих цветов.

## Структура страниц

- Каждая страница — один большой self-contained файл в `frontend/pages/*.js` (login, dashboard, operations, settings, pl, balance, planfact, receivables, import). Разбивки на мелкие переиспользуемые компоненты нет, кроме общего `Navbar.js`.
- `Navbar.js` общий для dashboard/pl/balance/planfact/receivables/operations, список вкладок там же (`NAV_ITEMS`, фильтруется через `can()`). `settings.js` и `import.js` Navbar не используют — у них свой header с отдельными кнопками в верхней панели ("⚙️ Настройки", "Импорт").

## Данные и авторизация на фронте

- Нет общего API-клиента: каждая страница хардкодит `axios.baseURL = 'http://localhost:8000/api'`.
- Сессия — в `localStorage` (`token`, `role`, `role_label`, `is_admin`, `permissions`, `name`), читается только в `useEffect`.
- `getPermissions()`/`can(perms, section, action)` копипастой в каждой странице (источник истины — `Navbar.js`).
- Новым экранам/секциям нужен соответствующий `section` из `SECTIONS` в `backend/app/permissions.py`, иначе права доступа не заработают.

## Язык

UI полностью на русском, часть строк сравнивается буквально (статусы, группы статей, названия банков). При генерации текста использовать существующую терминологию проекта (Статья, Контрагент, Отсрочка, Дебиторка, П&Л, ДДС), а не синонимы.

## Что нужно на выходе от Claude Design

1. Готовый JSX с инлайн `style={{}}`, без Tailwind-классов и CSS-in-JS библиотек.
2. Цвета — значения из палитры выше, либо явно помеченные новые CSS-переменные (для добавления в `globals.css`).
3. Один файл на экран, а не дерево из мелких компонентов.
4. Явное указание, какую существующую страницу концепт заменяет или дополняет.
